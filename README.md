# 合同与付款里程碑台账

用于本地合同、付款里程碑与收付款记录管理的命令行项目。

需要 Python 3.12，无第三方依赖（仅标准库 `sqlite3`）。在仓库根目录运行：

```bash
python3 -m contract_ledger --help
python3 -m contract_ledger --version
python3 -m unittest discover -s tests -v
```

## 数据存储

所有业务数据持久化在项目内固定位置的本地 SQLite 数据库：
`.contract_ledger/ledger.db`（首次写操作时自动创建）。退出进程后重新
运行仍能读到既有记录。每次写操作在单个事务内完成，任何校验失败都会
整体回滚，不会留下半写入记录。

测试可用环境变量 `CONTRACT_LEDGER_DB` 指向临时数据库以隔离数据。

## 子命令

### 登记合同

```bash
python3 -m contract_ledger register-contract \
    --code HT-001 --customer 甲方公司 --date 2026-01-15 --amount 10000.50
```

- 合同编号全局唯一，重复登记以非零状态退出且不改动既有数据。
- 初始金额必须为正数，最多两位小数；签订日期必须为 `YYYY-MM-DD`。
- 成功后输出合同编号与当前金额（此时等于初始金额）。

### 登记变更单

```bash
python3 -m contract_ledger register-change \
    --contract HT-001 --code CHG-01 --description 追加需求 --delta 2000 \
    [--milestone MS-01]
```

- 变更单编号全局唯一；说明非空；变动可正可负、最多两位小数、不得为零。
- 登记后为**草稿**状态，不影响合同当前金额。
- 省略 `--milestone` 时归属合同总额（既有行为不变）；指定时里程碑编号
  必须存在且属于 `--contract` 所指合同，否则拒绝。

### 登记付款里程碑

```bash
python3 -m contract_ledger register-milestone \
    --contract HT-001 --code MS-01 --name 首付款 --amount 4000 --due 2026-03-01
```

- 里程碑编号全局唯一，重复登记以非零状态退出且不改动既有数据；名称非空。
- 金额为正数、最多两位小数；到期日为 `YYYY-MM-DD`，且不得早于该合同
  签订日期，否则拒绝。
- 成功后输出里程碑编号。

### 更新里程碑到期日

```bash
python3 -m contract_ledger set-milestone-due --code MS-01 --due 2026-04-15
```

- 新到期日必须为 `YYYY-MM-DD`，不得早于合同签订日期，也不得早于已对该
  里程碑生效（且未作废）的变更单中最晚的变更生效日期。
- 任一条件不满足则拒绝，原到期日保持不变；成功后输出里程碑编号与新到期日。

### 变更生效

```bash
python3 -m contract_ledger effect-change --code CHG-01
```

- 草稿 → 已生效，变动计入当前金额，同时记录当天为变更生效日期：
  当前金额 = 初始金额 + 全部已生效且未作废变更单的变动之和。
- 若生效后当前金额小于等于零则拒绝，金额与状态保持原样。
- 归属里程碑的变更单还须满足：生效后该里程碑当前金额（初始金额 +
  该里程碑下已生效且未作废变更合计）大于零，否则同样拒绝。

### 变更作废

```bash
python3 -m contract_ledger void-change --code CHG-01
```

- 已生效变更单作废后，其变动从当前金额中移除；若作废后当前金额
  小于等于零则拒绝。
- 草稿也可直接作废，金额不变（草稿里程碑变更单作废同样不做金额校验）；
  已作废记录保留可查，不得再生效。

### 查询合同

```bash
python3 -m contract_ledger query-contract --code HT-001
```

输出客户名称、签订日期、初始金额、当前金额；随后是“里程碑：”段，按登记
先后逐行列出里程碑编号、名称、到期日与当前金额（当前金额 = 初始金额 +
该里程碑下已生效且未作废变更合计；无里程碑时输出“里程碑：无”）；最后
列出全部变更单（按登记先后排列）的编号、变动、状态与归属——合同级标
“归属：合同”，里程碑级标“归属：<里程碑编号>”。查询不改动任何数据；
编号不存在则以非零状态退出并说明原因。

### 登记发票

```bash
python3 -m contract_ledger issue-invoice \
    --contract HT-001 --code INV-001 --milestone MS-01 \
    --amount 4000 --date 2026-02-01
```

- 发票号全局唯一，重复登记以非零状态退出且不改动既有数据；发票号可用
  `--code`、`--invoice` 或直接以位置参数提供。
- 里程碑必须存在且属于 `--contract` 所指合同，否则拒绝。
- 金额为正数、最多两位小数；开票日期为 `YYYY-MM-DD`，且不得早于该合同
  签订日期。
- 成功后输出发票号、所属里程碑编号与金额。新发票状态为 `unpaid`。

### 登记收款

```bash
python3 -m contract_ledger record-payment \
    --invoice INV-001 --code PAY-001 --amount 1200 --date 2026-02-10
```

- 收款单号全局唯一；金额为正数、最多两位小数；收款日期不得早于发票日期。
- 当某发票下累计收款大于发票金额时，只按发票剩余额度入账，超出部分
  转记为**该合同的超额收款余额**，不得丢弃；该笔收款同时保存收款总额、
  入账金额与超收金额。
- 累计收款恰好等于发票金额时发票立即置为 `paid`；因超额收款导致累计
  大于发票金额时同样视为 `paid`。作废（`void`）发票不可再登记收款。
- 成功后输出收款单号、发票号、收款金额、入账金额与超收金额。

### 作废发票

```bash
python3 -m contract_ledger void-invoice --invoice INV-001
```

- 仅状态为 `unpaid` 的发票可作废；`paid` 发票拒绝作废，已为 `void`
  的发票重复作废拒绝，发票号不存在同样拒绝。
- 作废只改变发票状态：该发票已有收款记录的已收金额、超收余额以及
  合同累计超额收款余额均保持作废前数值不变。
- 作废后该发票状态在 `query-payment` 中显示为字面值 `void`，此后
  再向该发票登记收款一律拒绝。
- 校验失败时非零状态退出、原因写标准错误，状态与全部金额保持不变。

### 查询收款

```bash
python3 -m contract_ledger query-payment --contract HT-001 [--as-of 2026-06-30]
```

输出为写到标准输出的 **JSON 数组**（不改动任何数据）。每张发票按登记
先后对应一个元素，字段固定为：

| 字段 | 含义 |
| --- | --- |
| `invoice` | 发票号 |
| `milestone` | 里程碑编号 |
| `amount` | 发票金额（元，数字） |
| `status` | 字面值 `paid` / `unpaid` / `void` |
| `received` | 已收金额（元，数字） |
| `excess` | 该发票超收余额（元，数字） |
| `overdueDays` | 逾期天数（整数）：观察日期晚于该发票所属里程碑到期日时为相差天数，早于或恰好等于到期日时为 `0` |
| `overdueAmount` | 逾期未收金额：`status` 为 `unpaid` 时等于发票金额减已收金额，`paid` 或 `void` 时为 `0` |

数组末尾额外追加一个汇总元素，只含两个字段：

- `totalExcess`：合同累计超额收款余额（元，数字）；
- `totalOverdueAmount`：全部发票 `overdueAmount` 之和（元，数字）。

`--as-of` 指定观察日期（`YYYY-MM-DD`），省略时按运行当天。金额字段
一律为元的数字（可含两位小数，无货币符号与千分位）。`--as-of` 格式
非 `YYYY-MM-DD` 或日期非法时以非零状态退出、原因写标准错误、标准
输出为空且不改动任何数据；合同编号不存在同样非零退出且不改动数据。

## 错误处理

金额格式非法、日期不合法、编号缺失或重复、引用不存在的合同、里程碑、
发票编号、里程碑与合同不匹配、里程碑余额不为正、状态不允许的流转、
向作废发票登记收款等，一律在写入前整体失败：非零状态退出，原因输出到
标准错误，不改动任何既有金额、状态、到期日、发票、收款或余额。
所有金额比较前统一按分归一，日期比较均按 `YYYY-MM-DD` 规范文本进行。
