# 合同与付款里程碑台账

用于本地合同、付款里程碑与收付款记录管理的命令行项目。

需要 Python 3.12，无第三方依赖（仅标准库 `sqlite3`）。在仓库根目录运行：

```bash
python3 -m contract_ledger --help
python3 -m contract_ledger --version
python3 -m unittest discover -s tests -v
```

## 数据存储

所有业务数据持久化在项目内固定位置的本地 SQLite 数据库：
`.contract_ledger/ledger.db`（首次写操作时自动创建）。退出进程后重新
运行仍能读到既有记录。每次写操作在单个事务内完成，任何校验失败都会
整体回滚，不会留下半写入记录。

测试可用环境变量 `CONTRACT_LEDGER_DB` 指向临时数据库以隔离数据。

## 子命令

### 登记合同

```bash
python3 -m contract_ledger register-contract \
    --code HT-001 --customer 甲方公司 --date 2026-01-15 --amount 10000.50
```

- 合同编号全局唯一，重复登记以非零状态退出且不改动既有数据。
- 初始金额必须为正数，最多两位小数；签订日期必须为 `YYYY-MM-DD`。
- 成功后输出合同编号与当前金额（此时等于初始金额）。

### 登记变更单

```bash
python3 -m contract_ledger register-change \
    --contract HT-001 --code CHG-01 --description 追加需求 --delta 2000 \
    [--milestone MS-01]
```

- 变更单编号全局唯一；说明非空；变动可正可负、最多两位小数、不得为零。
- 登记后为**草稿**状态，不影响合同当前金额。
- 省略 `--milestone` 时归属合同总额（既有行为不变）；指定时里程碑编号
  必须存在且属于 `--contract` 所指合同，否则拒绝。

### 登记付款里程碑

```bash
python3 -m contract_ledger register-milestone \
    --contract HT-001 --code MS-01 --name 首付款 --amount 4000 --due 2026-03-01
```

- 里程碑编号全局唯一，重复登记以非零状态退出且不改动既有数据；名称非空。
- 金额为正数、最多两位小数；到期日为 `YYYY-MM-DD`，且不得早于该合同
  签订日期，否则拒绝。
- 成功后输出里程碑编号。

### 更新里程碑到期日

```bash
python3 -m contract_ledger set-milestone-due --code MS-01 --due 2026-04-15
```

- 新到期日必须为 `YYYY-MM-DD`，不得早于合同签订日期，也不得早于已对该
  里程碑生效（且未作废）的变更单中最晚的变更生效日期。
- 任一条件不满足则拒绝，原到期日保持不变；成功后输出里程碑编号与新到期日。

### 变更生效

```bash
python3 -m contract_ledger effect-change --code CHG-01
```

- 草稿 → 已生效，变动计入当前金额，同时记录当天为变更生效日期：
  当前金额 = 初始金额 + 全部已生效且未作废变更单的变动之和。
- 若生效后当前金额小于等于零则拒绝，金额与状态保持原样。
- 归属里程碑的变更单还须满足：生效后该里程碑当前金额（初始金额 +
  该里程碑下已生效且未作废变更合计）大于零，否则同样拒绝。

### 变更作废

```bash
python3 -m contract_ledger void-change --code CHG-01
```

- 已生效变更单作废后，其变动从当前金额中移除；若作废后当前金额
  小于等于零则拒绝。
- 草稿也可直接作废，金额不变（草稿里程碑变更单作废同样不做金额校验）；
  已作废记录保留可查，不得再生效。

### 登记发票

```bash
python3 -m contract_ledger invoice \
    --contract HT-001 --milestone MS-01 --code INV-01 \
    --amount 4000 --date 2026-03-01
```

- 发票编号全局唯一，重复登记以非零状态退出且不改动既有数据。
- `--milestone` 必须存在且属于 `--contract` 所指合同，否则整单失败不落库。
- 开票金额为正数、最多两位小数，且不得超过该里程碑当前金额
  （初始金额＋该里程碑下已生效且未作废变更合计），超出拒绝不落库。
- 开票日期为 `YYYY-MM-DD`，不得早于该里程碑到期日。
- 发票登记后即已开具，无草稿态；成功后输出“发票编号：<编号>”。

### 登记收款

```bash
python3 -m contract_ledger receive \
    --invoice INV-01 --code RCV-01 --amount 1500 --date 2026-03-05
```

- 收款流水号全局唯一，重复登记以非零状态退出且不改动既有数据。
- 发票必须已开具；收款金额为正数、最多两位小数；收款日为
  `YYYY-MM-DD`，不得早于该发票开票日期。
- 同一发票可多次登记收款（部分收款），但收款合计不得超过发票金额，
  超出则拒绝且不新增本次收款。
- 成功后输出“收款流水号：<编号>”。

### 按合同登记分配收款

```bash
python3 -m contract_ledger allocate-receipt \
    --contract HT-001 --code RCV-02 --date 2026-03-10 \
    --alloc INV-01 1500 --alloc INV-02 2500.50
```

- 一笔银行流水同时分配到同一合同下的多张发票：`--alloc` 可重复，
  每条为“发票编号 + 分配金额”，至少一条；同一发票编号在一次
  操作中至多出现一次。
- 收款流水号全局唯一（与普通收款共用同一编号空间），重复以非零
  状态退出且不改动任何数据；收款日为 `YYYY-MM-DD`，不得早于任一
  被分配发票的开票日期。
- 分配金额为正数、最多两位小数；每条分配项引用的发票必须存在且
  属于 `--contract` 所指合同；任一发票的累计已收金额（含此前收款
  与本次分配）不得超过其开票金额。
- 全部校验通过后单事务落库：一条收款记录，金额等于各分配金额之和；
  任一校验失败则整体拒绝，不落任何分配。成功后输出一行
  “收款流水号：<编号>”。

### 查询合同

```bash
python3 -m contract_ledger query-contract --code HT-001
```

输出客户名称、签订日期、初始金额、当前金额；随后是“里程碑：”段，按登记
先后逐行列出里程碑编号、名称、到期日与当前金额（当前金额 = 初始金额 +
该里程碑下已生效且未作废变更合计；无里程碑时输出“里程碑：无”）；最后
列出全部变更单（按登记先后排列）的编号、变动、状态与归属——合同级标
“归属：合同”，里程碑级标“归属：<里程碑编号>”。随后是“发票：”段，
按登记先后逐行列出发票编号、所属里程碑、开票金额、开票日期、已收金额
与状态（`未收款`／`部分收款`／`已收齐`，分别对应已收为零、已收大于零
小于发票金额、已收等于发票金额；无发票时输出“发票：无”）；最后是
“收款：”段，按登记先后逐行列出该合同全部收款的收款流水号、所属发票、
金额与收款日，末尾追加分配明细——普通收款显示“分配：整笔归 <发票编号>”，
分配收款按操作内分配项先后显示“分配：<发票编号> <金额> …”（无收款时
输出“收款：无”）。查询不改动任何数据；
编号不存在则以非零状态退出并说明原因。

## 错误处理

金额格式非法、日期不合法、编号缺失或重复、引用不存在的合同或里程碑
编号、里程碑与合同不匹配、里程碑余额不为正、开票金额超过里程碑当前
金额、收款合计超过发票金额、分配收款缺少分配项或分配项重复/越界、
状态不允许的流转等，
一律在写入前整体失败：非零状态退出，原因输出到标准错误，不改动任何
既有金额、状态或到期日。日期比较均按 `YYYY-MM-DD` 规范文本进行。
